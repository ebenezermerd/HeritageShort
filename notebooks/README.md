# Kaggle notebooks

The pipeline runs on your own computer, except the two jobs that need a GPU:
moving shots (Wan 2.2) and the score (ACE-Step). Those run here, by hand, because
Kaggle's free GPU is a notebook, not an API. The files are generated by
`build_notebooks.py` so the code is easy to read as text.

**Nothing in these notebooks has been run on Kaggle yet.** Try them in this order,
and write down in `FAILURES.md` whatever breaks.

## One-time setup

1. `make kaggle-bundle` creates `outputs/kaggle_bundle.zip` (the storyboard, the
   Wan job file and the 9:16 keyframes of the shots that will move).
2. On Kaggle, create a new Dataset called **heritage-short-bundle** and upload the
   contents of that zip. Notebooks read it at `/kaggle/input/heritage-short-bundle`.
3. In each notebook: Accelerator **GPU T4 x2**, Internet **on**, add that dataset.

## Order

1. `00_smoke.ipynb`: about 2 minutes. Shows the GPU, VRAM and free disk. Write the
   remaining weekly GPU quota from Kaggle's sidebar into `COSTS.md`.
2. `10_acestep.ipynb`: three instrumental score candidates from the storyboard's
   `music` block. Download `/kaggle/working/music/` into `outputs/music/raw/`.
3. `20_wan.ipynb`: four clips (shots 1, 3, 6, 8), 480x832, 81 frames. It saves each
   clip as it finishes and skips ones already saved, so after a timeout just run it
   again. Download `/kaggle/working/shots/` into `outputs/shots/raw/`.
4. Download `notebook_log.jsonl` each time and keep it in `outputs/kaggle_logs/`.
   Its seconds-per-clip numbers are the GPU minutes that go in `COSTS.md`.
5. `30_likeness.ipynb` stays locked until `ETHICS.md` holds both brothers' exact
   photo-upload messages.

Back on your computer, `make film` picks the downloaded files up. A clip that is
missing or too short is replaced by a Ken Burns pass and logged as a fallback.
